With a partner: The firm wants the case tracker VM on a paralegal’s everyday workstation. Type 1 or Type 2, and why?

Type 2 fits the client side. It installs like any application on the OS the workstation already runs, so the desktop stays and the VM runs beside it. Type 1 takes the whole machine and suits dedicated hosts.
BPC170 · 8.1
Uses for virtualization

Why lift a machine? Four client-side jobs.

  • SandboxingTest risky changes in a box you can throw away.
  • Legacy OS hostingKeep an older OS alive inside a modern machine.LAW-07’s exit
  • Cross-platformRun another platform’s software on the desk you have.
  • Training and labsPractice environments that reset without consequences.

Beyond the client: servers host extra network nodes as VMs, and desktop virtualization hands employees a VM desktop.

Resource requirements

Spec the host before you lift the machine.

  • CPUVirtualization extensions, enabled in BIOS or UEFI firmware.
  • MemoryEach VM’s share must meet its OS minimum.
  • StorageOne shared physical disk, separate logical disks.
  • NetworkVM to VM, VM to host, VM to the host’s network.

BPC170 · 8.1
Check: Slow guest

Commit: the case tracker VM crawls. First check?

With a partner: The VM boots, then everything drags. The host’s disk has room to spare. Which resource do you audit first, and where?

Memory. The VM’s allocation must meet the minimum its OS and apps need, and every running guest draws from the same physical pool. Check the VM’s share first, then count what the other guests are holding.

BPC170 · 8.2
Check: Move the workload

Commit: which model takes the case tracker as-is?

  1. SaaS: subscribe to a cloud case-tracking application.
  2. IaaS: rent servers, storage, and networking, and run the VM there.
  3. PaaS: rebuild the app on a cloud development platform.
IaaS moves the VM unchanged. Rented infrastructure runs the firm’s own VM, older OS and all. SaaS would swap the app for a provider’s, and PaaS would mean a rebuild. Either may come later. The VM can move today.
